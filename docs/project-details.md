# 프로젝트 발표 메모

자연어 처리(NLP, Natural Language Processing)는 사람이 쓰는 언어를 컴퓨터가 읽고 분석할 수 있도록 다루는 분야다. 문장에서 연락처를 찾거나 리뷰가 긍정인지 부정인지 판단하는 일이 여기에 해당한다.

이 프로젝트는 고객 문의와 리뷰에서 이메일·전화번호·날짜·금액·URL을 찾아 표준 형식으로 변환한다. 또 KNU 감성사전과 부정·강조 규칙을 이용해 문장의 감성을 판정한다. 기본 출력은 추출값과 점수 계산 근거를 담은 텍스트이며, `--format json`을 붙이면 같은 분석 결과를 JSON으로 받을 수 있다.

### (3) 날짜 정규식의 그룹과 수량자

| 코드 | 역할 |
| --- | --- |
| `(?P<year>[0-9]{4})` | 숫자 네 자리를 `year`라는 이름으로 저장 |

## 항목 3 · 점수와 평가

### (1) 사전 점수와 부정·강조 계산

KNU 사전의 -2~+2점 중 0점 항목을 빼고, `data/domain_lexicon.csv`의 [분야별 표현](../data/domain_lexicon.csv)을 추가. 부정어를 적용하면 점수의 부호가 바뀌고, 강조어를 적용하면 점수의 크기가 달라진다. `정말 좋지 않다` → **(+2) × (-1) × 1.5 = -3**.

```bash

```

`nlp/sentiment.py`: [사전 로딩과 점수 계산](../nlp/sentiment.py)

### (2) 정밀도와 재현율

| 지표 | 뜻 | 전화번호 평가 |
| --- | --- | --- |
| 정밀도 | 프로그램이 정답이라고 내놓은 값 중 실제 정답과 일치한 비율. 잘못 찾은 값이 많을수록 낮아진다. | 추출한 10개 중 10개 정답 → **100%** |
| 재현율 | 미리 준비한 전체 정답 중 프로그램이 실제로 찾아낸 비율. 놓친 정답이 많을수록 낮아진다. | 정답 11개 중 10개 추출 → **90.9%** |

**높은 정밀도와 낮은 재현율이 함께 나오는 이유**

정밀도를 높이기 위해 전화번호의 자릿수와 앞자리를 엄격하게 제한하면, 다른 숫자를 전화번호로 잘못 찾는 일이 줄어든다. 하지만 실제 번호인 `1588-1234`처럼 규칙에 맞지 않는 정답도 놓치기 때문에 재현율이 낮아진다. 이 평가에서는 잘못 찾은 번호가 없었지만 정답 하나를 놓쳤다.

**정밀도와 재현율 적용 방법**

`nlp/extract.py`가 찾은 값을 `evaluate.py`에서 정답 파일과 비교한다. 맞게 찾은 값(TP), 잘못 찾은 값(FP), 놓친 값(FN)을 센 뒤 정밀도는 `TP / (TP + FP)`, 재현율은 `TP / (TP + FN)`으로 계산한다. `tests/test_regression.py`는 추출 결과와 이 집계값이 예상대로 나오는지 확인한다.

`evaluate.py`: [추출 결과와 정답 비교](../evaluate.py#L41) · `README.md`: [유형별 평가표](../README.md#5-평가-결과)

### (3) 이중부정을 어디까지 처리하는지

- `좋지 않지 않다` → ‘좋지’의 기본 점수는 +2점. 바로 뒤의 ‘않지’에서 -2점, 이어지는 ‘않다’에서 다시 **+2점, 긍정**. 부정을 두 번 적용하면 부호가 원래대로 돌아옴.
- `영화가 재미없는 건 아니야` → 사전에 있는 ‘재미없’에서 -1점을 얻음. 사람은 ‘건 아니야’를 앞 표현을 다시 부정하는 말로 읽지만, 규칙은 ‘-지’ 뒤에 붙은 부정어처럼 정해진 어미와 인접한 말만 검사. 그래서 두 번째 부정을 적용하지 못해 **-1점, 부정**.

```bash
python -X utf8 main.py --text "좋지 않지 않다"
python -X utf8 main.py --text "영화가 재미없는 건 아니야"
```

`nlp/sentiment.py`: [부정어 처리 코드](../nlp/sentiment.py)

### (2) 규칙 기반 시스템의 유지보수가 어려운 이유

규칙 기반 시스템은 지원할 입력 형식이 늘어날 때마다 어떤 입력을 받고 어떤 입력을 거를지 직접 정해야 한다. 새 조건을 추가하면 기존 입력의 처리 결과도 달라질 수 있어, 수정한 부분과 관련된 동작을 함께 확인해야 한다.

### (3) 규칙 기반이 머신러닝보다 적합한 상황

이메일이나 전화번호처럼 찾을 값의 형식이 정해져 있다면, 자릿수나 구분자를 규칙으로 직접 검사할 수 있다. 머신러닝 모델을 학습시킬 자료가 부족하거나, 어떤 조건을 통과해 결과가 나왔는지 확인해야 할 때도 규칙 기반이 적합하다.

리뷰는 같은 단어라도 앞뒤 문맥에 따라 뜻이 달라진다. 이런 문장은 규칙을 추가해도 놓치는 경우가 생긴다. 정답 데이터가 충분하다면 다양한 표현을 학습하는 머신러닝이 더 나을 수 있다.

### (5) 복합·중립 감성을 단일 점수로 처리할 때의 설계

복합 감성은 한 문장 안에 긍정과 부정이 함께 담긴 경우다. 이 프로젝트는 표현별 점수를 더해 문장 전체를 하나의 점수로 나타내고, 합계가 양수면 긍정, 음수면 부정, 0이면 중립으로 표시한다.

사전을 불러올 때 감성 점수가 0인 항목은 미리 제외한다. 점수를 매길 표현이 없으면 합계가 0점이고, 복합 감성에서 긍정 점수와 부정 점수가 상쇄돼도 합계가 0점이다. 두 경우 모두 중립으로 표시된다.

| 입력 | 실제 계산 | 출력 |
| --- | --- | --- |
