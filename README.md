# 규칙 기반 한국어 정보 추출과 감성 분석

## 1. 프로젝트 개요

고객 문의와 리뷰에서 **이메일·전화번호·날짜·금액·URL을 추출하고 정규화**하며, **감성사전과 부정·강조 규칙으로 긍정·부정을 판단**하는 Python 프로그램이다.

```text
입력 문장
  ├─ 정보 추출: 정규표현식으로 탐지 → 유효성 확인 → 형식 통일
  └─ 감성 분석: 토큰화 → 사전 조회 → 부정·강조 적용 → 점수 합산
                                  ↓
                      추출 결과와 감성 계산 과정 출력
```

두 기능은 같은 문장을 따로 분석한다. 사람이 정한 규칙을 사용해 어떤 표현에 몇 점을 줬는지 보여 준다.

| 파일 | 역할 |
| --- | --- |
| [main.py](main.py) | 명령줄 입력, 통합 실행, 텍스트/JSON 출력 |
| [nlp/extract.py](nlp/extract.py) | 다섯 정보 유형의 정규식, 유효성 검사, 정규화 |
| [nlp/sentiment.py](nlp/sentiment.py) | 사전 준비, 토큰화, 감성 표현 조회, 규칙 적용 |
| [setup_data.py](setup_data.py) | 고정 버전의 외부 데이터 다운로드 및 SHA-256 검증 |
| [evaluate.py](evaluate.py) | 정답 데이터와 비교, 성능 지표와 오류 출력 |
| [tests/test_regression.py](tests/test_regression.py) | 추출·감성·평가·CLI 회귀 테스트 |

기존 README의 상세 설명과 확장 절차는 [프로젝트 상세 설명](docs/project-details.md)에 보존했다.

## 2. 설치 및 실행 방법

Python **3.10 이상**이 필요하다. 처음에만 인터넷으로 데이터를 받고, 이후에는 오프라인으로 실행할 수 있다.

```bash
git clone https://github.com/js910/rule-based-nlp.git
cd rule-based-nlp
python setup_data.py
python -X utf8 main.py --text "이 식당은 정말 맛있지 않았어요. 문의: support@example.com, 전화 02-1234-5678, 일시: 2024년 3월 15일, 참가비: 50,000원"
```

Conda 사용 시 `python setup_data.py` 전에 아래 명령으로 [environment.yml](environment.yml)의 환경을 준비한다. Python 3.10 이상이 이미 있으면 생략할 수 있다.

```bash
conda env create -f environment.yml
conda activate rule-based-nlp
```

### 기본 출력 예시

아래는 위 명령을 실행한 결과다. 토큰은 문장을 나눈 조각으로, 문장부호도 포함한다.

```text
=== 정보 추출 결과 ===
입력: 이 식당은 정말 맛있지 않았어요. 문의: support@example.com, 전화 02-1234-5678, 일시: 2024년 3월 15일, 참가비: 50,000원

추출 결과:
- 이메일: support@example.com
- 전화: 02-1234-5678
- 날짜: 2024-03-15
- 금액: 50000 KRW
- URL: 없음

=== 감성 분석 과정 ===
문장: 이 식당은 정말 맛있지 않았어요. 문의: support@example.com, 전화 02-1234-5678, 일시: 2024년 3월 15일, 참가비: 50,000원
분석 모드: 사전 + 부정·강조 규칙
1. 토큰화: [이, 식당은, 정말, 맛있지, 않았어요, ., 문의, :, support, example, ., com, ,, 전화, 02, 1234, 5678, ,, 일시, :, 2024, 년, 3, 월, 15, 일, ,, 참가비, :, 50, ,, 000, 원]
2. 감성 단어 탐지:
   - 맛있지 → 맛있 (+2)
3. 부정어 탐지:
   - 맛있지: '않았어요' → 감성 반전 (1회)
4. 강조어 탐지:
   - 맛있지: '정말' → 강도 ×1.5
계산: 맛있지 · (+2) × (-1) × 1.5 = -3

최종 점수: -3
최종 판정: 부정
```

### 옵션

```bash
# 다른 프로그램에서 사용할 기존 구조의 JSON 출력
python -X utf8 main.py --text "정말 좋지 않다" --format json

# 부정·강조 규칙을 끄고 사전만 사용한 결과 확인
python -X utf8 main.py --text "정말 좋지 않다" --baseline

# 합계 0점을 긍정으로 처리
python -X utf8 main.py --text "좋다. 나쁘다." --binary
```

기본 출력은 텍스트다. JSON이 필요하면 `--format json`을 붙인다.

## 4. 규칙 설계

### 정규표현식과 정규화

정규표현식은 전화번호의 자릿수처럼 글자의 모양을 정해 두고 찾는 규칙이다. 찾은 값은 아래처럼 일정한 형식으로 바꾼다.

| 유형 | 지원하는 변형 예시 | 정규화 |
| --- | --- | --- |
| 이메일 | `user@example.com`, `a.b@sub.example.com`, `a+tag@example.org` | 도메인만 소문자로 변환 |
| 전화 | `(02) 123-4567`, `031 1234 5678`, `01012345678`, `+82 10-1234-5678`, `공일공-일이삼사-오육칠팔` | 국내 하이픈 형식 |
| 날짜 | `2024년 2월 29일`, `2024/2/29`, `2024-02-29`, `2024.2.29` | 달력 검증 후 `YYYY-MM-DD` |
| 금액 | `10,000원`, `1억 2천만원`, `$100`, `₩2,500` | 정수 금액과 통화 코드 |
| URL | `http://example.com`, `https://example.com/a?q=1`, `www.example.com` | 스킴·호스트 소문자화, `www.`에 `https://` 추가 |

URL → 이메일 → 전화 → 날짜 → 금액 순서로 찾는다. URL 안에 날짜처럼 보이는 부분이 있어도 날짜로 다시 세지 않는다. 달력에 없는 날짜와 쉼표 위치가 틀린 금액도 제외한다.

### 감성사전에서 표현 찾기

같은 표현이 두 사전에 있으면 직접 추가한 사전의 점수를 쓴다. 문장을 나눈 뒤 여러 단어로 된 표현부터 찾고, 없으면 단어의 기본 부분을 찾는다. 예를 들어 `고마워`는 `고맙`으로 찾아본다.

### 부정·강조 규칙과 점수

```text
표현 점수 = 기본 사전 점수 × (-1)^부정 횟수 × 강조 가중치
문장 점수 = 찾은 표현 점수의 합
```

| 규칙 | 조건·처리 | 예시 |
| --- | --- | --- |
| 앞 부정 | 바로 앞 `안`·`못`으로 부호 반전 | `안 좋다` → -2 |
| 뒤 부정 | `-지` 계열 어미 뒤 `않다`·`못하다` 계열 표현 | `좋지 않다` → -2 |
| 이중부정 | `-지 않지 않다`와 지원 활용형 | `좋지는 않지는 않아요` → +2 |
| 일반 강조 | 매우·정말·아주·너무·무척·진짜 → ×1.5 | `정말 좋다` → +3 |
| 강한 강조 | 완전·엄청·굉장히 → ×2 | `완전 좋다` → +4 |
| 약화 | 조금·약간 → ×0.5 | `조금 좋다` → +1 |

가장 가까운 강조어 하나를 적용한다. `완전 정말 좋다`는 ‘정말’만 반영해 +3점이다. `정말 안 좋다`는 부정과 강조를 함께 적용해 -3점이다.

합계가 양수면 긍정, 음수면 부정, 0이면 중립이다. `--binary`를 붙이면 0점을 긍정으로 처리한다. `--baseline`은 부정·강조를 끄고 사전 점수만 더한다.

## 5. 평가 결과

### 정보 추출

직접 만든 60문장으로 평가했다. TP는 맞게 찾은 값, FP는 잘못 찾은 값, FN은 놓친 값이다. 정밀도는 찾은 값 중 맞은 비율이고, 재현율은 정답 중 찾아낸 비율이다.

| 유형 | TP | FP | FN | Precision | Recall |
| --- | ---: | ---: | ---: | ---: | ---: |
| 이메일 | 10 | 0 | 2 | 100.0% | 83.3% |
| 전화 | 10 | 0 | 1 | 100.0% | 90.9% |
| 날짜 | 9 | 0 | 2 | 100.0% | 81.8% |
| 금액 | 9 | 0 | 2 | 100.0% | 81.8% |
| URL | 9 | 1 | 2 | 90.0% | 81.8% |

직접 만든 60문장에서 얻은 결과다. 실제 고객 문의에서도 같은 수치가 나오는지는 확인하지 않았다.

### 감성 분석: 규칙 적용 전후

기본 모드는 0점을 중립으로 예측한다. NSMC 정답은 긍정·부정뿐이므로 중립 예측은 오답으로 집계한다.

| 설정 | 정답 수 / 전체 | Accuracy | 긍정 F1 | 부정 F1 | Macro F1 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 사전만 | 19,492 / 49,997 | 39.0% | 0.557 | 0.460 | 0.509 |
| 사전 + 부정·강조 규칙 | 19,725 / 49,997 | 39.5% | 0.562 | 0.464 | 0.513 |

정확도는 맞힌 리뷰의 비율이다. F1은 얼마나 정확하게 찾았고 얼마나 놓치지 않았는지 함께 보는 점수다. Macro F1은 긍정과 부정 F1의 평균이다. 규칙을 적용해 정답이 233건 늘었다.

0점을 긍정으로 처리하는 `--binary` 조건도 별도로 비교했다.

| 이진 설정 | 정답 수 / 전체 | Accuracy | Macro F1 |
| --- | ---: | ---: | ---: |
| 전부 긍정 예측 기준선 | 25,171 / 49,997 | 50.3% | 0.335 |
| 사전만 | 30,458 / 49,997 | 60.9% | 0.577 |
| 사전 + 규칙 | 30,591 / 49,997 | 61.2% | 0.580 |

규칙의 효과는 0점 처리 방식이 같은 표 안에서 비교한다. 사전을 다듬을 때 본 리뷰를 다시 평가에 썼으므로, 새 리뷰에서도 같은 성능이 나오는지는 확인하지 않았다.

## 7. 한계와 개선 방향

- 대표번호와 유로를 인식하도록 규칙을 넓힌다. 날짜 규칙을 넓힐 때는 주문번호를 잘못 잡는지도 확인한다.
- 붙여 쓴 문장과 줄임말을 더 잘 찾도록 개선한다. 새 리뷰를 따로 모아 효과를 확인한다.
- 점수를 합산하므로 음식은 좋고 가격은 나쁘다는 평가를 항목별로 보여 주기 어렵다. 비꼬는 말이나 앞뒤 뜻을 함께 봐야 하는 문장도 놓칠 수 있다.
- 전화번호처럼 형식이 일정한 값은 규칙으로 찾기 쉽다. 비슷한 문서를 찾는 데는 단어의 쓰임을 숫자로 나타내는 TF-IDF 같은 방법을 비교해 볼 수 있다.
