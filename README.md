# 규칙 기반 한국어 정보 추출과 감성 분석

고객 문의나 리뷰에서 이메일, 전화번호, 날짜, 금액, URL을 추출하고, 감성 단어와 앞뒤 표현을 바탕으로 문장 전체의 긍정·부정을 판정한다. 결과는 분석 근거를 포함한 JSON으로 출력한다.

## 설치 및 실행

Python 3.10 이상이 필요하다. 외부 패키지 없이 실행된다. 저장소 루트에서 다음 명령을 실행한다.

```powershell
python -m pip install -r requirements.txt
python main.py --text "상품이 정말 좋지 않았어요. 문의: help@example.com, 전화 02-1234-5678, 접수 2024년 3월 15일, 배송비 5,000원, 링크 https://example.com/help"
python evaluate.py
```

예시 출력에서 접수일은 `2024-03-15`, 배송비는 `{"amount": 5000, "currency": "KRW"}`다. `좋지 않았어요`는 `좋`의 기본 점수 `+2`를 반전하고 `정말`의 가중치 `1.5`를 곱해 `-3`이 된다. 출력의 `hits`에서 단어별 기본 점수, 부정 횟수, 가중치, 최종 점수를 확인할 수 있다. `--baseline`을 추가하면 사전 점수만 합산한다.

### 정규표현식

| 유형 | 지원 예 | 정규화 |
| --- | --- | --- |
| 이메일 | `user@example.com`, `user.name@sub.example.co.kr`, `user+orders@example.org` | 도메인을 소문자로 바꾸고 로컬 파트는 원문 유지 |
| 전화 | `010-1234-5678`, `(02) 123-4567`, `031 1234 5678`, `01012345678` | `지역·서비스 번호-국번-가입자 번호` 형식 |
| 날짜 | `2024년 1월 15일`, `2024/01/15`, `2024-01-15`, `2024.1.15` | `YYYY-MM-DD`, 달력에 없는 날짜 제외 |
| 금액 | `10,000원`, `1억 2천만원`, `$100`, `₩2,500` | 정수 `amount`와 `currency`를 함께 반환 |
| URL | `http://example.com`, `https://example.com/path?q=1`, `www.example.com` | 스킴과 호스트를 소문자로 바꾸고 `www.`로 시작하면 `https://` 추가 |

`[0-9]{3,4}`처럼 수량자로 자릿수를 제한한다. `(?:…)`는 캡처 없이 선택지를 묶고, `(?P<year>…)`는 후처리에 필요한 값을 이름으로 캡처한다. 날짜의 `(?P=sep)`는 연·월·일 사이의 구분자가 같은지 확인한다. `(?<![0-9])` 같은 전후방 검사는 긴 번호 일부를 잘못 추출하는 일을 줄인다. URL과 이메일 내부의 문자열은 다른 유형의 값으로 중복 집계하지 않는다.

### 감성 점수

1. 한글과 영숫자 어절을 분리하고 절 경계에 쓰이는 문장부호를 보존한다. 어절에서 사전과 일치하는 가장 긴 어간을 찾으며, 일부 조사와 활용형을 허용한다.
2. `안 좋다`, `좋지 않다`, `친절하지 못하다`는 부정 1회로 보고 점수의 부호를 반전한다. `좋지 않지 않다`는 부정 2회를 적용해 `+2`가 된다.
3. `정말`, `매우` 등은 점수에 1.5를 곱하고 `완전`, `엄청` 등은 2를 곱한다. `조금`, `약간`은 0.5를 곱한다.
4. 가중 점수를 합산해 양수면 긍정, 음수면 부정, 0이면 중립으로 출력한다.

## 평가 결과

정보 추출은 60문장 전체에서 유형별 정규화 값의 출현 횟수를 비교했다. 정밀도는 `TP / (TP + FP)`, 재현율은 `TP / (TP + FN)`이다. 잘린 값은 거짓 양성 1개와 놓친 정답 1개로 집계한다.

| 유형 | TP | FP | FN | 정밀도 | 재현율 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 이메일 | 10 | 0 | 2 | 100.0% | 83.3% |
| 전화 | 9 | 0 | 2 | 100.0% | 81.8% |
| 날짜 | 9 | 0 | 2 | 100.0% | 81.8% |
| 금액 | 9 | 0 | 2 | 100.0% | 81.8% |
| URL | 9 | 1 | 2 | 90.0% | 81.8% |

감성 분석은 두 설정에서 같은 토큰화, 사전, 104문장을 사용했다. 점수가 0인 중립 예측은 긍정·부정 평가에서 오답으로 집계했다. Macro F1은 긍정과 부정 F1의 산술평균이다.

| 설정 | 정답 수 | 정확도 | 긍정 F1 | 부정 F1 | Macro F1 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 사전만 | 62/104 | 59.6% | 0.673 | 0.659 | 0.666 |
| 사전 + 부정·강조 규칙 | 85/104 | 81.7% | 0.860 | 0.894 | 0.877 |

`좌석은 나쁘지 않았어요`는 `-2`에서 `+2`로 바뀌었다. `예쁘지만 너무 질겨요`는 사전 점수만 합산하면 `0`이고, `질겨요`에 강조 가중치를 적용하면 `-1`이다. 평가 문장은 규칙과 함께 작성한 소규모 예제이므로, 점수는 이 문장 모음에서의 결과다.

## 규칙 기반과 통계 기반의 활용 범위

정규표현식은 구조가 분명한 이메일과 날짜의 추출에 적합하다. 감성 사전도 어떤 단어와 규칙이 점수를 바꿨는지 문장별로 설명할 수 있다. 표기 변형을 넓히면 다른 문자열과 충돌할 수 있고, 업종이 바뀔 때는 감성 표현과 가중치를 다시 검토해야 한다.

TF-IDF와 코사인 유사도는 문서 집합에서 단어의 상대적 중요도와 문서 간 유사도를 구하는 데 적합하다. 레이블이 있는 리뷰로 분류기를 학습하면 명시적으로 나열하지 않은 단어의 통계적 단서도 활용할 수 있다. 반대로 문서 유사도만으로 정해진 형식의 전화번호를 찾아 정규화하기는 어렵다. 이 프로젝트에서는 두 접근의 적용 범위를 비교하고, 성능 수치는 규칙 기반 설정끼리 측정했다.

정보 추출의 다음 단계로는 국제화 주소와 다양한 통화 표기를, 감성 분석에서는 관용구, 부정 범위, 배송과 제품을 구분하는 항목별 감성을 다룰 수 있다.
